# China Travel Buddy — 产品规格说明（Spec）

> 版本：v0.4 原型 · 最后更新：2026-10-23 · 产品方案见 Claude Docs《China Travel Buddy · SPEC v0.4 产品方案》（本文件描述代码实现，已完成其中第 1 步“结构调整”） · 代码仓库：`muuflyinsky/china-travel-app`（`main` 分支）
> 本文描述**当前代码实际实现的行为**，以及已知限制和待决问题。评审时请对照代码；文中“未验证”的条目代表还没有在真机或真实 Key 下测过。

---

## 1. 产品概述

**一句话**：帮外国游客在中国“吃得安心、走得明白、付得出钱、住得进去”的手机网页 App（PWA）。

**目标用户**
| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 首次来华的外国游客（主力） | 出发前 2–4 周 + 在华 3–14 天 | 签证/支付/上网准备；看懂菜单；不迷路；订酒店和火车 |
| 有食物过敏或宗教饮食限制的游客 | 每顿饭 | 不吃错东西，能跟服务员说清楚 |
| 商务/长住外国人（次要） | 在华 | 翻译、支付、打车 |

**不做的事（当前范围外）**：机票酒店自营交易、用户账号体系、社区 UGC、离线地图、中国手机号/实名代办。

**商业模式**：OTA / eSIM 联盟佣金（主），后续可加会员和 B 端多语言菜单。

## 2. 信息架构

底部 5 个主标签（iOS 规范：常驻可见、不隐藏、不出现“更多”）+ 两个二级页面（带“返回”）。

```
Today（首页）  Eat（菜单）  Explore（探索，原 Go）  Stay（住宿）  Talk（翻译 + 所有给人看的卡）
   │
   ├─ ⚙ Settings（设置）          /settings   —— 每个主页面右上角齿轮进入
   └─ Emergency（紧急求助）       /sos        —— Today 底部和 Talk 都有入口
```
v0.4 把 Pay、Mobile data、Before you go 三个独立页面并入 Today。旧地址仍可打开并重定向：`/pay` → `/#pay`，`/esim` → `/#data`，`/prepare`、`/essentials` → `/`，`/go` → `/explore`。

### 2.1 Today 按出行阶段变化（`lib/phase.ts`）
阶段由日期和定位**自动判断**，没有手动的 Planning / In China 开关：

| 阶段 | 判断条件 | 显示的卡片 |
|---|---|---|
| before 出发前 | 到达日期在未来、未填，或行程已结束 | 免签结果 · 到达倒计时 · 每个目的地城市的精选酒店 · 准备清单（支付、上网、App、火车和景点、注意事项，每项可展开，即原来的三个独立页面） · 试用菜单 |
| arrival 到达当天 | 到达日期 = 今天 | 城市和天气 · 一键确认入境日期 · 回酒店卡 · 拍菜单 · 支付 |
| in_china 在中国 | 已确认入境、到达日期已过，或定位在中国境内（`profile.locatedInChina`） | 城市和天气 · 拍菜单 · 去哪里 · 支付快捷入口 + 汇率换算 · 停留倒计时 |
| leaving 离境前 3 天 | 离开日期 − 3 天起，且人在中国 | 停留倒计时 · 去机场（跳到 Explore 搜“机场”） · 退税提醒 · 支付 |

紧急求助在任何阶段都在首页底部。尚未实现：预约提醒、城市离线包、抵达机场指南（SPEC v0.4 第 2–4 步）。

**少输入原则**：语言和本国货币从浏览器推断；国籍从浏览器地区 / 时区猜测，用户点一下确认；入境方式由免签结果自动带出（设置页仍可改）；到达日期过后首页问一次“你是 X 月 X 日入境的吗？”，一键确认；过敏在第一次打开 Eat 时问一次，“我没有过敏”是第一个选项；Stay 默认用行程日期，人数记住上次；酒店地址拍预订截图识别。

## 3. 功能规格

每项给出：用户能做什么 → 实现方式 → 验收标准 → 已知限制。

### 3.1 Eat · 菜单识别（核心功能）
- **输入**：拍照（手机摄像头 `capture=environment`），或手动输入/粘贴菜名。
- **处理**：照片在手机端压缩到最长边 1600px（JPEG 0.85），发到 `/api/menu`，由大模型返回结构化 JSON（`lib/llm.ts` 中的 `MenuSchema`）。请求带上：目标语言、当前城市（让模型按当地做法推断，如川菜和粤菜版本不同）。
- **每道菜输出**：中文原名、拼音、翻译名、字面意思、描述、分类、价格、配料（标注“菜单上写的”还是“按标准做法推断”）、过敏原（欧盟 14 类 + 味精）、肉类类型、是否素食、是否含酒、辣度 0–3、置信度、备注。
- **个性化**：与用户设置的过敏原/饮食限制比对，冲突的菜红框 + 红色警告条，列出命中的**全部**过敏原；顶部汇总卡显示“N 道不适合你”，可筛选；菜价旁显示换算后的本国货币。辣度图标用中性色（红色只表示过敏危险，绿色只表示安全）。
- **结果页**：出结果后输入区收起成“再拍一张 / 键盘”一行，页面滚到结果。
- **多道菜点单**：每道菜有“加入”按钮（含过敏原时变成“加入·不要放 X”），加入后变成数量步进器；底部常驻“出示点单 · N 道菜”和圆形过敏卡按钮。
- **给服务员看**（`components/ShowCard.tsx`）：点单卡 `你好，我要点：` + 每道菜 `×数量`（需要时加“（不要放…）”）+ 过敏说明；卡片上用用户语言解释“这张卡写了什么”；底部给服务员三个一键回复（可以，没问题 / 这道菜做不了 / 里面有 X），点了以后用用户语言显示“服务员说：…”。
- **验收**：一份 15 道菜的清晰菜单 40 秒内返回；每道菜都有翻译、拼音和至少 3 个配料；用户过敏原命中时必须标红。
- **已知限制**：配料是推断，不保证准确，页面有免责提示；模型未在真实菜单上做系统评测（见 §9）。

### 3.2 Explore · 探索（原 Go）
- 地点搜索（英文、拼音、中文），范围是当前城市；附近：地铁、厕所、药店、ATM、便利店、医院（需要定位）。
- 选中地点后：中文名、拼音、地址；**“在高德中导航”**（主按钮，带上当前位置作为起点）、打车卡、Apple 地图。导航一律交给高德，App 内不再计算路线（已删除 `/api/route` 和 `planRoutes`）。
- 支持 `/explore?q=机场` 这类深链接（离境阶段的“去机场”卡使用）。
- 定位：浏览器 GPS（WGS-84）在服务端转为 GCJ-02 再逆地理编码。
- 待做（第 3 步）：城市精选“看 / 吃”各 5 条、预约提醒。

### 3.3 Stay · 住宿（主要收入，SPEC v0.4 第 2 步）
- **行程条**：顶部一行“城市 · 日期 · 晚数 · 人数 · 编辑”，代替原来的 4 个输入框。城市默认取 Today 链接带来的城市（`/stay?city=`）→ 行程第一个城市 → 当前所在城市；日期默认取行程日期；人数记在 profile 里，用步进器改。
- **四档价格**（分段控件，默认“舒适”）：经济 < ¥400 · 舒适 ¥400–800 · 高档 ¥800–1500 · 奢华 ≥ ¥1500，下面同时显示本国货币换算。分档边界可按城市覆盖（`lib/hotel-tiers.ts` 的 `CITY_BOUNDS`，目前为空，等有真实价格数据再填）。
- **每档 1 张精选大卡 + 2 个紧凑行**：大卡显示中文名、品牌英文名、区、“通常可接待外宾（连锁酒店）”或“大城市 N 星酒店”、最近地铁站和距离、评分、高德参考价（¥ + 本国货币），**全页唯一的金色按钮**“在 Trip.com 查价格”，旁边是高德地图；紧凑行用蓝色文字链接。
- **自动精选规则**（`lib/hotels.ts`，不需要人工）：高德酒店 POI（通用查询 + 万豪、希尔顿、洲际、凯悦、全季、亚朵等品牌查询）→ 只保留国际连锁、国内大连锁，或主要城市（`TRIP_CITY_ID` 里的城市）的四/五星酒店 → 没有价格的去掉 → 按价格分档 → 每档前 6 个查最近地铁站（1.5 km 内）→ 排序：接待外宾的把握（国际连锁 > 国内连锁 > 仅星级）→ 地铁距离分段（≤500 m / ≤1 km / 更远 / 没有）→ 评分 → 价格只作平局时的加分项。每档取 3 个。文案只写“通常可接待外宾”，不写“已核实”。
- **缓存**：每个城市的结果在内存和 `data/hotels/<adcode>.json` 里保存 7 天（含生成时间，页面显示“更新于”）。Vercel 上文件系统只读，只有内存缓存。
- 底部：“Trip.com 上 {城市} 的全部酒店”链接、选取规则说明（并写明没有酒店付费上榜，对应欧盟付费排名披露）、佣金说明、护照提示。**飞猪链接已删除。**
- **出发前 Today**：每个目的地城市一行“{城市}的酒店”，副标题是该城市“舒适”档第一名和价格，点进 Stay 的对应城市；没填城市时提示去设置里添加。
- **未验证**：高德 v5 POI 的 `business.cost` 对酒店是否稳定有值（没有价格的酒店会被丢掉）；品牌名单需要按真实返回结果再补；区域（离景点远近）还没参与排序。

### 3.4 Talk · 翻译 + 所有“给人看”的卡
- 双向翻译（用户语言 ↔ 中文），语音输入和朗读；中文结果附拼音；可全屏。“翻译”按钮始终可点，内容为空时提示先输入。
- **给人看**：打车卡（进入 Explore 选目的地）、过敏卡、回酒店卡（拍订单截图识别）、紧急求助。规则：要给中国人看的东西都在 Talk。
- 离线短语本：5 类 28 句。

### 3.5 支付（并入 Today）
- 出发前：准备清单“支付”一项展开为支付宝 / 微信绑卡步骤、手续费说明、带少量现金。
- 在中国：首页“支付”区有一键打开支付宝付款码、扫一扫、微信；“价格换算”就地展开（¥ → 本国货币，超过 ¥200 显示含约 3% 外卡手续费的金额）。
- **未验证**：跳转链接未在真机测试。

### 3.6 上网 / eSIM（并入 Today）
- 准备清单“上网”一项：只推荐一家（Airalo，`components/prep/EsimPicker.tsx` 的 `RECOMMENDED`），一个金色按钮；其余 5 家收在“其他选项”里；本地 SIM 卡说明。
- 准备清单一次只展开一项，所以一屏最多一个金色按钮。

### 3.7 出发前准备（并入 Today）
免签查询是出发前首页第一张卡；线上入境卡提示在其下方。App 清单、火车（金色按钮）/ 机票 / 景点门票（文字链接）、注意事项都在准备清单里。

### 3.8 停留倒计时（在华模式）
- 输入：入境日期、入境方式（免签 30 天 / 240 小时过境 / 签证 N 天）。
- 规则：停留期从**入境次日 0 时**起算，最后一天 = 入境日 + N 天（`lib/stay.ts`）。日期一律按 UTC 日历日计算和显示，避免夏令时切换时少算一天（例：10 月 18 日入境、30 天 → 11 月 17 日，过去在欧洲时区会错显示 11 月 16 日）。
- 入境方式默认由免签结果带出。
- 输出：第几天 / 最晚离境日期 / 剩余天数（≤3 天标红，超期给警告）；“加入日历”生成 `.ics` 文件，提前 3 天和当天各提醒一次。
- **待确认**：起算规则需对照国家移民管理局原文再核对一次（§10）。

### 3.9 Settings · 设置
iOS 分组列表，每行 = 名称 + 当前值 + “›”，点进去是编辑页（`components/EditSheet.tsx`）。支持 `/settings#dates`、`#entry`、`#allergies` 等深链接直接打开对应编辑页。
1. **你**：护照（换护照会同时更新入境方式和本国货币）· 语言 · 本国货币
2. **我的行程**：日期（到达–离开）· 入境方式（注明“来自护照”；编辑页里才有入境日期和签证天数）· 城市
3. **饮食**：隐私说明放在本组顶部 · 过敏（按中餐常见度排序，先显示 11 项，其余在“更多”；每项可标“严重：微量也不行”，严重时过敏卡和点菜卡加上“请用干净的锅和工具”）· 饮食限制
4. **关于**：我们如何赚钱 · 隐私 · 版本号
5. **清除所有数据**（红色，二次确认）

没有做：离线包管理、提醒开关（对应功能还没有）、发送反馈（需要确定反馈邮箱或渠道）。所有数据只存在 localStorage。

### 3.10 Emergency · 紧急求助
110 / 120 / 119 / 122 / 12345 一键拨号；“我需要帮助”中文全屏卡；附近医院；护照丢失处理步骤。

### 3.11 免签查询
- **流程**：猜国籍（浏览器地区 → 时区）→ “你持有 X 国护照吗？”点“是”或换一个（可搜索的国家列表）→ 只有“仅符合 240 小时过境”的护照才追问一句“是否飞往第三国？”→ 结果卡。
- **结果卡**：一句结论（如“免签 · 最多 30 天”）、最多 3 条条件、行程超过允许天数或到达日期晚于政策截止日时显示琥珀色提醒、数据来源和**核对日期**。
- **数据**：`lib/visa.ts` 手工维护，**不让模型判断**。单方面免签 50 国（至 2026-12-31；文莱无截止日）、互免 28 国（资料称 29 国，缺的一国未核实，没有猜测补上）、240 小时过境 57 国。海南 59 国免签暂未建模。
- **维护规则**：每月对照国家移民管理局名单核对一次；**每年 12 月中旬必须核对**（单方面免签目前到 12 月 31 日）。每次核对都要更新 `VERIFIED_ON`，用户能看到这个日期。
- **上线前**：名单尚未逐条对照 NIA 官方名单核实。

### 3.12 回酒店卡
- 在 Talk 和到达当天的首页：“添加我的酒店”→ 拍预订截图 → `/api/hotel` 用视觉模型读出中文酒店名和地址 → 存到本地。之后一键出示“师傅您好，请带我回酒店：…”大字卡。
- 目前用 Claude 识图；如果改用国产模型，和菜单识别一起换（§10）。

## 4. 全国城市支持
- `lib/data/cities.json`：2,213 个地点（369 个地级市 + 县级市/县），含行政区划代码、英文名、拼音、所属省、上级城市。由 `scripts/build-cities.mjs` 从 `china-division` 数据集生成（处理了民族自治州名称，常用英文名用通行写法，如 Harbin、Kashgar）。
- 城市选择器：英文/拼音/中文搜索，热门目的地排前（搜 “wuyuan” 先出江西婺源）。
- 当前城市全局共享（`components/useCity.ts`）：天气、搜索、附近、酒店、出发城市、景点门票、菜单推断都跟着它走；已授权定位时自动识别。

## 5. 多语言
- **界面**：英语、西班牙语、法语、德语、日语、韩语（`lib/i18n/*.ts`，TypeScript 强制每种语言字段齐全）。切换后所有页面即时生效。
- **菜单识别与翻译输出**：15 种语言（`lib/languages.ts`）。界面不支持的语言自动用英文界面。
- **展示给中国人看的内容**一律是中文。

### 6.1 API 一览
| 路由 | 作用 |
|---|---|
| `POST /api/menu` | 菜单照片/菜名 → 结构化菜单 |
| `POST /api/translate` | 文本翻译 + 拼音 |
| `GET /api/places` | 高德 POI 搜索（城市内或周边） |
| `GET /api/regeo` | GPS（WGS-84）→ GCJ-02 + 城市信息 |
| `GET /api/weather` | 天气预报（首页只显示今天） |
| `GET /api/hotels` | 城市精选酒店（按价格分档，`?city=<adcode>&name=<城市简称>`） |
| `POST /api/hotel` | 预订截图 → 酒店中文名、地址、英文名 |
| `GET /api/fx` | 汇率（欧洲央行参考汇率；取不到时用内置近似值） |
| `GET /api/go` | 联盟跳转：生成带佣金参数的链接并记录点击 |
| `GET /api/app-icon/[id]` | 从 App Store 获取并缓存 App 图标（`?store=1` 跳转商店页） |
| `GET /api/status` | 哪些 Key 已配置（前端用来显示“示例数据”提示） |

### 6.2 演示模式
未配置 `ANTHROPIC_API_KEY` / `AMAP_KEY` 时，对应接口返回上海的示例数据，前端显示“Sample data”提示。

### 7.1 联盟跳转流程
```
用户点“查价格” → /api/go?partner=trip&kind=hotel_search&…
  → 服务器拼出 Trip.com 链接，带上 Allianceid、SID、trip_sub3，以及本次点击编号 trip_sub1
  → 记录点击（时间、来源页面、城市、日期、点击编号）
  → 302 跳转到 Trip.com
```
`trip_sub1` 会出现在 Trip.com 后台的订单报表里，可以逐笔对账。格式是“位置标签-随机编号”，例如 `stay-comfort-1-3f9a0c2b7d1e` = Stay 页、舒适档、第 1 张卡；`stay-all-…` = 底部“全部酒店”链接。用来比较各档位和卡片位置的转化（`goLink(…, tag)`，标签只允许小写字母、数字和连字符，≤ 24 字符）。只允许跳到白名单内的合作方，不存在开放跳转漏洞。

## 8. 合规与隐私（当前做法 + 风险）
- **服务器在境外**（香港/新加坡）：不需要 ICP 备案；但《个人信息保护法》第 3、53 条和《生成式人工智能服务管理暂行办法》第 20 条仍可能适用，主要风险是域名被拦截。详见 `BRAINSTORM.md` §三。
- **Anthropic 使用政策**：Anthropic 不向中国大陆提供服务，并且限制由中国公司持股超过 50% 的企业使用。运营主体是否适用需要确认（§10）。
- **敏感个人信息**：过敏史属于健康信息，目前只存本地、不上传。上线前需要隐私政策和单独同意。
- **地图**：只调用高德接口并跳转高德/苹果地图，不在 App 内自绘底图，因此不涉及审图号问题。

## 0. v0.5 变更（按时刻重排，先安全和真实）

**P0 安全与真实**
- **严重过敏原拦截**：模型给每个配料标 `role`（main / sauce / garnish）和配料自身的过敏原。用户标为“严重”的过敏原如果是某道菜的主料，这道菜不能加入点菜卡，显示“含 X（主料），严重过敏不建议点”，也不提供“问能不能不放”。不能追溯到酱料或配菜的过敏原一律按主料处理（`lib/allergens.ts` 的 `mainAllergens`）。演示：严重花生过敏时宫保鸡丁无法加入。
- **点菜卡重排**（`components/ShowCard.tsx`）：
  - 顺序：① 严重过敏一句话（红色、最大字）→ ② 菜名 × 份数 → ③ 其他过敏原和“用干净的锅和工具”。
  - 字号从 36px 逐级缩到 28px，尽量一屏放下；服务员回复按钮固定在底部，最多 3 个；用户语言说明默认折叠。
  - 实测 390×844 下，2 道菜 + 1 个严重过敏原一屏看全，回复按钮可见（英、法、德）。
- **AI 改为 OpenAI 兼容接口**（`lib/llm.ts` 的 `structured()`）：
  - 环境变量 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL_VISION`、`AI_MODEL_TEXT`，默认阿里云百炼（图片 qwen3-vl-plus、文字 qwen-plus）；模型不存在时按顺序换下一个（图片：qwen-vl-max、qwen-vl-max-latest、qwen3-vl-flash、qwen-vl-plus），并记住能用的那个。不设 `AI_BASE_URL` 时先试新加坡站，Key 被拒（401/403）再试北京站，因为百炼的 Key 只能在创建它的地域使用。
  - 自检：打开 `/api/ai-check`，返回实际使用的地域、模型名，以及文字和图片模型各一次极小调用的结果和错误原文（不含 Key）。
  - 模型回复的小偏差先自动修正再校验：过敏原写法（peanuts → peanut）、缺字段、大小写、字符串形式的配料等。无法识别的过敏原会把这道菜标为低置信度；菜品过敏原总包含各配料的过敏原。回复被截断时让模型简短重答。
  - 错误分开显示：422（回复无法解析）提示重拍；AI 服务出错（Key、额度、超时）提示“菜单识别暂时没有响应”。两种情况都在服务器日志里记录原因（`[ai]`、`[menu]`）。
  - JSON Schema 由 zod 生成并放进提示词，回复用 zod 校验，失败重试一次；仍失败返回 422，界面显示“没读清楚，请再拍一次”，不显示半截结果。
  - 只有在没有 `AI_API_KEY` 时才使用 Claude（`ANTHROPIC_API_KEY`）。
  - 20 份真实菜单的过敏原评测：`node scripts/eval-menus.mjs <网址> eval/menus`，需要你准备照片和 `expected.csv`。**尚未运行**（开发环境连不上百炼，也没有真实菜单）。
- **生产环境不显示示例数据**：缺 Key 时接口返回 503 并记录错误，界面显示“暂时不可用”。示例数据只在开发环境出现；公开演示可设 `ALLOW_SAMPLE_DATA=1`。
- **文案**：酒店改为“连锁酒店 · 通常可接待外宾”；免签问句改为“您的护照：{国家}？”这类句式，不再把国名直接拼进句子（6 种语言）。

## 1. 产品概述

**一句话**：帮外国游客在中国“吃得安心、走得明白、付得出钱、住得进去”的手机网页 App（PWA）。

**目标用户**
| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 首次来华的外国游客（主力） | 出发前 2–4 周 + 在华 3–14 天 | 签证/支付/上网准备；看懂菜单；不迷路；订酒店和火车 |
| 有食物过敏或宗教饮食限制的游客 | 每顿饭 | 不吃错东西，能跟服务员说清楚 |
| 商务/长住外国人（次要） | 在华 | 翻译、支付、打车 |

**不做的事（当前范围外）**：机票酒店自营交易、用户账号体系、社区 UGC、离线地图、中国手机号/实名代办。

**商业模式**：OTA / eSIM 联盟佣金（主），后续可加会员和 B 端多语言菜单。

## 2. 信息架构

底部 5 个主标签（iOS 规范：常驻可见、不隐藏、不出现“更多”）+ 两个二级页面（带“返回”）。

```
Today（首页）  Eat（菜单）  Explore（探索，原 Go）  Stay（住宿）  Talk（翻译 + 所有给人看的卡）
   │
   ├─ ⚙ Settings（设置）          /settings   —— 每个主页面右上角齿轮进入
   └─ Emergency（紧急求助）       /sos        —— Today 底部和 Talk 都有入口
```
v0.4 把 Pay、Mobile data、Before you go 三个独立页面并入 Today。旧地址仍可打开并重定向：`/pay` → `/#pay`，`/esim` → `/#data`，`/prepare`、`/essentials` → `/`，`/go` → `/explore`。

### 2.1 Today 按出行阶段变化（`lib/phase.ts`）
阶段由日期和定位**自动判断**，没有手动的 Planning / In China 开关：

| 阶段 | 判断条件 | 显示的卡片 |
|---|---|---|
| before 出发前 | 到达日期在未来、未填，或行程已结束 | 免签结果 · 到达倒计时 · 每个目的地城市的精选酒店 · 准备清单（支付、上网、App、火车和景点、注意事项，每项可展开，即原来的三个独立页面） · 试用菜单 |
| arrival 到达当天 | 到达日期 = 今天 | 城市和天气 · 一键确认入境日期 · 回酒店卡 · 拍菜单 · 支付 |
| in_china 在中国 | 已确认入境、到达日期已过，或定位在中国境内（`profile.locatedInChina`） | 城市和天气 · 拍菜单 · 去哪里 · 支付快捷入口 + 汇率换算 · 停留倒计时 |
| leaving 离境前 3 天 | 离开日期 − 3 天起，且人在中国 | 停留倒计时 · 去机场（跳到 Explore 搜“机场”） · 退税提醒 · 支付 |

紧急求助在任何阶段都在首页底部。尚未实现：城市离线包、抵达机场指南（SPEC v0.4 第 2–4 步）。

**少输入原则**：语言和本国货币从浏览器推断；国籍从浏览器地区 / 时区猜测，用户点一下确认；入境方式由免签结果自动带出（设置页仍可改）；到达日期过后首页问一次“你是 X 月 X 日入境的吗？”，一键确认；过敏在第一次打开 Eat 时问一次，“我没有过敏”是第一个选项；Stay 默认用行程日期，人数记住上次；酒店地址拍预订截图识别。

## 3. 功能规格

每项给出：用户能做什么 → 实现方式 → 验收标准 → 已知限制。

### 3.1 Eat · 菜单识别（核心功能，v0.5 P1.7 已实现）
- **输入**：拍照（`capture=environment`），或手动输入菜名（每行一道，逗号、顿号也可分隔）。
- **两步取数 + 流式返回**（`lib/dishes.ts`，`POST /api/menu` 返回 NDJSON）：
  1. 看图模型**只认字**：`[{zh, price, printed}]`（`printed` = 菜名旁印的配料/说明）+ 菜系。
  2. 每道菜先查菜品知识库（`lib/dish-cache.ts`），命中立即返回；未命中的每 4 道一批、最多 4 批并行交给文本模型，每批一返回就推给前端。提示词用紧凑示例代替完整 JSON Schema。
  3. 前端逐道渲染，显示“已读 3 / 约 12”和进度条，未到的菜显示占位卡。
  - 每次记录耗时到日志：`[menu] read=…ms cache=命中/总数 generate=…ms total=…ms`；前端埋点 `menu_first_dish`（首道菜耗时）、`menu_done`。
- **列表只回答“能不能点”**（`lib/verdict.ts`）：每张卡 = 外文菜名 + 价格（等宽数字）、中文 + 拼音、一行描述（≤10 词）、**一个结论** + “+ 加入”。
  - 结论：可以点（绿）/ 先问一下 · 原因（琥珀，过敏原只在酱料或配菜里、含酒、太辣、模型不确定）/ 别点 · 原因（红，过敏原是主料、不符合素食/清真/不吃猪牛肉）。原因文字可换行，不截断。
  - “别点”的菜在全部读完后排到最后并调淡；顶部筛选：全部 / 可以点 / 先问 / 别点（数量为 0 的不显示）。没设过敏和饮食限制时不显示结论。
  - 点菜建议收成一行“N 条点菜建议 ›”。
  - 390×844 下一屏完整显示 3 道菜（已在浏览器验证）。
- **点开 = 底部详情面板**：菜名、价格、中文 + 拼音 + 朗读、字面意思；结论说明；配料分“菜单上写的 / 通常会放”，命中过敏原的标红；注意事项；“这道菜信息不对”（匿名）。
  - 详情由 `POST /api/dish` 点开时再取（知识库命中直接返回，前端同一会话内缓存）。详情里发现的新过敏原会并入结论，**只会变严格**。
  - 操作：过敏原只在酱料/配菜里时，“加入，不要 X”（X = 所有带该过敏原的配料，如豆瓣酱、酱油）；严重过敏原是主料时**没有加入按钮**。
- **点菜卡**（`components/ShowCard.tsx`，P0-2）：`蚂蚁上树 ×1（不要放豆瓣酱、酱油）`，只列这道菜需要去掉的配料。
- **菜品知识库**（Supabase，可选）：表结构见 `supabase/migrations/0001_dishes.sql`，只存菜的通用知识，不存用户数据和照片。键 = 规范化菜名（`lib/dish-name.ts`：繁转简、去价格份量、去“招牌/特色/秘制”前缀和“（XX店）”后缀；**保留“老”**，因为老醋花生、老鸭汤是菜名本身）+ 省级代码。查询顺序 (菜名, 本省) → (菜名, 通用)。只缓存 high；medium 7 天过期；low 不缓存；`PROMPT_VERSION` 变化即失效；被标记“不对”的条目不再返回。带菜单印字的菜视为店家版本，不走缓存。未配置 `SUPABASE_URL` 时只在内存缓存（每个服务器实例）。
- **评测**：`scripts/eval-menus.mjs` 已改为读流式结果，并对每道菜取详情检查配料数。
- **未完成**：`scripts/seed-dishes.mjs`（约 300 道常见菜预生成）；用 20 份真实菜单比较 qwen-flash 与现模型的过敏原漏标；Supabase 项目尚未创建。

### 3.2 Explore · 探索（原 Go）
- 地点搜索（英文、拼音、中文），范围是当前城市；附近：地铁、厕所、药店、ATM、便利店、医院（需要定位）。
- 选中地点后：中文名、拼音、地址；**“在高德中导航”**（主按钮，带上当前位置作为起点）、打车卡、Apple 地图。导航一律交给高德，App 内不计算路线。支持 `/explore?q=机场`、`/explore?tab=eat` 深链接。
- **城市精选（SPEC v0.4 第 3 步）**：没在搜索时显示“看 / 吃”各 5 条，第一条大卡，其余是紧凑行，点一下换到大卡。
  - 景点卡：英文名 + 中文名、简介、建议游玩时长、最佳时间、评分；**门票**（金色，Trip.com，`trip_sub1=explore-sight-N-…`）、打车卡、高德路线；需要预约的景点有琥珀色条，打开**预约提醒**。
  - 菜卡：菜名（用户语言）+ 中文 + 拼音、简介、过敏原（命中用户过敏的标红）、辣度、素食、当地“供应这道菜的餐厅人均”；**点菜卡**（含用户全部过敏原）和**附近哪里能吃**（高德实时搜这道菜，按评分再按距离排序）。
  - 每条都有 👎“没有帮助”，底部写明“根据高德数据自动选取，介绍由 AI 撰写”和生成日期，以及“Trip.com 上 {城市} 的热门景点”链接。
  - Eat 页（还没拍菜单时）有“{城市}吃什么”入口，和这里共用同一份数据。
- **预约提醒**（`components/ReservationSheet.tsx`）：选游玩日期 → 显示该日门票的开售时间（**换算到用户手机时区**，并注明北京时间）→ “设闹钟”生成带提醒的 `.ics` 并存到本地；在 Today（出发前和在中国阶段）显示 48 小时内的开售提醒。同时列出爽约后果、当日票、周一闭馆、预约渠道、官方网站和分步指南。
  - 数据：`lib/reservations.ts`，从开源项目 [Awesome China Travel Booking](https://github.com/caistrong/awesome-china-travel-booking)（CC BY 4.0，作者在 2026-10-05 至 08 核对过官网）转成结构化数据，页面上署名。目前 11 个景点：故宫、国家博物馆、天安门广场、慕田峪、上海博物馆（人民广场馆）、兵马俑、陕西历史博物馆、成都熊猫基地、灵隐寺、南京博物院、布达拉宫。**不生成放票时间**；上游更新时需要重新导入。

### 3.2.1 城市精选的自动化方案（覆盖所有热门城市）
- **哪些城市**：`lib/data/hot-cities.json`，目前 46 个热门城市。加一个城市 = 加一行 adcode，下个月自动生成。
- **怎么生成**（`lib/city-guide.ts`，不需要人工）：
  1. 景点：高德“风景名胜”和“博物馆”POI → 去掉停车场、售票处、入口等 → 国家级景点和评分优先 → 取 5 个。
  2. 文字：模型只根据这些字段写简介、最佳时间、建议时长，一次输出 6 种界面语言；**不许写价格、开放时间、放票时间**；不确定的标“低置信度”，页面隐藏简介。
  3. 代表菜：模型列出 5 道本地菜 → 用菜单识别的同一套流程算过敏原、辣度、是否素食 → 用高德搜索供应这道菜的餐厅，取人均消费的中间 50% 作为价格区间。
  4. 预约：按景点名匹配 `lib/reservations.ts`。
- **存放与刷新**：
  - 预生成文件 `public/city-guide/<adcode>.json`（静态，走 CDN）；没有文件时前端调 `/api/city-guide`，服务器当场生成并缓存 30 天。
  - 只有热门城市会生成，防止被刷接口；强制刷新需要 `CITY_GUIDE_TOKEN`。
  - **每月自动刷新**：`.github/workflows/city-guides.yml` 每月 1 日运行，构建 App、启动、运行 `scripts/build-city-guides.mjs` 生成全部城市，把变化提交到 `main`，Vercel 自动重新部署。需要在 GitHub 仓库 Settings → Secrets 里添加 `AMAP_KEY`（必需）和 `AI_API_KEY`（可选；没有时只生成高德部分，标记为 partial）。
- **人工环节（被动）**：低置信度条目和用户 👎 写入 `data/review.jsonl`（Vercel 上写到日志），只需要偶尔看一下。
- **成本估算**：每个城市 1 次文字生成 + 1 次菜品分析 + 约 8 次高德请求；46 个城市每月一次。

### 3.2.2 餐厅推荐：米其林 · 黑珍珠 · 大众点评必吃榜
- **只推荐上榜餐厅，并标出奖项**。徽章是纯文字，不使用各指南的商标图形，颜色用中性色（红、绿、琥珀和金色另有用途）：`MICHELIN ★★`、`MICHELIN Bib Gourmand`、`MICHELIN Selected`、`Black Pearl 黑珍珠 ◆◆`、`Dianping Must-Eat 必吃榜 2026`。
- **出现的位置**：
  - Explore“吃”标签下的“获奖餐厅”列表（每城最多 8 家）。
  - 所有搜索结果和地点卡（地图结果按名称匹配上榜餐厅）。
  - “附近哪里能吃”：上榜餐厅排最前，再按评分、距离排序。
- **统一排序**：米其林三星 > 黑珍珠三钻 > 米其林二星 > 黑珍珠二钻 > 米其林一星 > 黑珍珠一钻 > 必比登 > 必吃榜 > 米其林入选；同时上多个榜的略微加分。
- **匹配规则**（`lib/restaurant-awards.ts`）：
  - 品牌名必须一致（忽略“餐厅/饭店/酒家/餐馆/菜馆”后缀和全角括号）。
  - 榜单写了分店时，地图结果也必须是同一家分店；不写分店则匹配同城所有分店。
  - 宁可漏标，不可错标。
- **数据**：`lib/data/restaurant-awards.json`，用 `scripts/import-awards.mjs` 从 CSV 导入（模板 `scripts/awards-template.csv`）。每个榜单记录版本、来源和核对日期，页面上显示。导入新版本会替换该榜单的旧条目。**目前是空的**：这个开发环境访问不了米其林和美团的网站，我没有凭记忆填任何奖项。
- **更新节奏**（以往的发布时间）：黑珍珠每年 1 月（2026 版：内地 32 城 263 家）；必吃榜每年 6 月（2026 版：264 城 4,279 家）；米其林中国内地各城市指南全年陆续发布。每次发布后导入一次。
- **合规（待决）**：
  - 米其林和黑珍珠是公开发布的名单。只引用餐厅名和奖项、注明来源，是常见做法。
  - 必吃榜的完整数据只在大众点评 App 里，美团对数据抓取很敏感（大众点评诉百度地图不正当竞争案判百度败诉）。**整批导入必吃榜之前，建议先取得美团 / 大众点评授权，或走开放平台合作。**
  - 页面上已写明“各指南发布的奖项；我们与这些指南无关，没有餐厅付费上榜”。
- **演示模式**用的是虚构店名（“示例本帮菜馆”等），避免给真实餐厅安上不存在的奖项。

### 3.3 Stay · 住宿（主要收入，SPEC v0.4 第 2 步）
- **行程条**：顶部一行“城市 · 日期 · 晚数 · 人数 · 编辑”，代替原来的 4 个输入框。城市默认取 Today 链接带来的城市（`/stay?city=`）→ 行程第一个城市 → 当前所在城市；日期默认取行程日期；人数记在 profile 里，用步进器改。
- **四档价格**（分段控件，默认“舒适”）：经济 < ¥400 · 舒适 ¥400–800 · 高档 ¥800–1500 · 奢华 ≥ ¥1500，下面同时显示本国货币换算。分档边界可按城市覆盖（`lib/hotel-tiers.ts` 的 `CITY_BOUNDS`，目前为空，等有真实价格数据再填）。
- **每档 1 张精选大卡 + 2 个紧凑行**：大卡显示中文名、品牌英文名、区、“通常可接待外宾（连锁酒店）”或“大城市 N 星酒店”、最近地铁站和距离、评分、高德参考价（¥ + 本国货币），**全页唯一的金色按钮**“在 Trip.com 查价格”，旁边是高德地图；紧凑行用蓝色文字链接。
- **自动精选规则**（`lib/hotels.ts`，不需要人工）：高德酒店 POI（通用查询 + 万豪、希尔顿、洲际、凯悦、全季、亚朵等品牌查询）→ 只保留国际连锁、国内大连锁，或主要城市（`TRIP_CITY_ID` 里的城市）的四/五星酒店 → 没有价格的去掉 → 按价格分档 → 每档前 6 个查最近地铁站（1.5 km 内）→ 排序：接待外宾的把握（国际连锁 > 国内连锁 > 仅星级）→ 地铁距离分段（≤500 m / ≤1 km / 更远 / 没有）→ 评分 → 价格只作平局时的加分项。每档取 3 个。文案只写“通常可接待外宾”，不写“已核实”。
- **缓存**：每个城市的结果在内存和 `data/hotels/<adcode>.json` 里保存 7 天（含生成时间，页面显示“更新于”）。Vercel 上文件系统只读，只有内存缓存。
- 底部：“Trip.com 上 {城市} 的全部酒店”链接、选取规则说明（并写明没有酒店付费上榜，对应欧盟付费排名披露）、佣金说明、护照提示。**飞猪链接已删除。**
- **出发前 Today**：每个目的地城市一行“{城市}的酒店”，副标题是该城市“舒适”档第一名和价格，点进 Stay 的对应城市；没填城市时提示去设置里添加。
- **未验证**：高德 v5 POI 的 `business.cost` 对酒店是否稳定有值（没有价格的酒店会被丢掉）；品牌名单需要按真实返回结果再补；区域（离景点远近）还没参与排序。

### 3.8 停留倒计时（在华模式）
- 输入：入境日期、入境方式（免签 30 天 / 240 小时过境 / 签证 N 天）。
- 规则：停留期从**入境次日 0 时**起算，最后一天 = 入境日 + N 天（`lib/stay.ts`）。日期一律按 UTC 日历日计算和显示，避免夏令时切换时少算一天（例：10 月 18 日入境、30 天 → 11 月 17 日，过去在欧洲时区会错显示 11 月 16 日）。
- 入境方式默认由免签结果带出。
- 计划离境日超过最晚合法离境日时显示超期警告（见 §0 P0-6）；倒计时按两者中较早的一天。
- 输出：第几天 / 最晚离境日期 / 剩余天数（≤3 天标红，超期给警告）；“加入日历”生成 `.ics` 文件，提前 3 天和当天各提醒一次。
- **待确认**：起算规则需对照国家移民管理局原文再核对一次（§10）。

### 3.11 免签查询
- **流程**：猜国籍（浏览器地区 → 时区）→ “你持有 X 国护照吗？”点“是”或换一个（可搜索的国家列表）→ 只有“仅符合 240 小时过境”的护照才追问一句“是否飞往第三国？”→ 结果卡。
- **结果卡**：一句结论（如“免签 · 最多 30 天”）、最多 3 条条件、行程超过允许天数或到达日期晚于政策截止日时显示琥珀色提醒、数据来源和**核对日期**。
- **数据**：`lib/visa.ts` 手工维护，**不让模型判断**。单方面免签 50 国（至 2026-12-31；文莱无截止日）、互免 28 国（资料称 29 国，缺的一国未核实，没有猜测补上）、240 小时过境 57 国。海南 59 国免签暂未建模。
- **维护规则**：每月对照国家移民管理局名单核对一次；**每年 12 月中旬必须核对**（单方面免签目前到 12 月 31 日）。每次核对都要更新 `VERIFIED_ON`，用户能看到这个日期。
- **上线前**：名单尚未逐条对照 NIA 官方名单核实。

|---|---|---|
| `ANTHROPIC_API_KEY` | 菜单识别、翻译 | 真实菜单必需 |
| `CLAUDE_MODEL` | 模型选择（默认 `claude-opus-5-5`；`claude-sonnet-5-5` 约半价；`claude-haiku-5-5` 约 1/40） | 否 |
| `AMAP_KEY` | 高德 Web 服务 Key | 真实地图必需 |
| `TRIP_ALLIANCE_ID` / `TRIP_SID` / `TRIP_SUB3` | Trip.com 联盟参数 | 佣金必需 |
| `TRIP_HOST` | Trip.com 站点（默认 `www.trip.com`） | 否 |
| `FLIGGY_PID` | 淘宝联盟 PID（飞猪） | 否 |
| `ESIM_<供应商>_URL` | 各 eSIM 联盟推广链接（AIRALO / HOLAFLY / SAILY / NOMAD / KLOOK） | 否，未填则无佣金 |

### 7.1 联盟跳转流程
```
用户点“查价格” → /api/go?partner=trip&kind=hotel_search&…
  → 服务器拼出 Trip.com 链接，带上 Allianceid、SID、trip_sub3，以及本次点击编号 trip_sub1
  → 记录点击（时间、来源页面、城市、日期、点击编号）
  → 302 跳转到 Trip.com
```
`trip_sub1` 会出现在 Trip.com 后台的订单报表里，可以逐笔对账。格式是“位置标签-随机编号”，例如 `stay-comfort-1-3f9a0c2b7d1e` = Stay 页、舒适档、第 1 张卡；`stay-all-…` = 底部“全部酒店”链接。用来比较各档位和卡片位置的转化（`goLink(…, tag)`，标签只允许小写字母、数字和连字符，≤ 24 字符）。只允许跳到白名单内的合作方，不存在开放跳转漏洞。

## 8. 合规与隐私（当前做法 + 风险）
- **服务器在境外**（香港/新加坡）：不需要 ICP 备案；但《个人信息保护法》第 3、53 条和《生成式人工智能服务管理暂行办法》第 20 条仍可能适用，主要风险是域名被拦截。详见 `BRAINSTORM.md` §三。
- **Anthropic 使用政策**：Anthropic 不向中国大陆提供服务，并且限制由中国公司持股超过 50% 的企业使用。运营主体是否适用需要确认（§10）。
- **敏感个人信息**：过敏史属于健康信息，目前只存本地、不上传。上线前需要隐私政策和单独同意。
- **地图**：只调用高德接口并跳转高德/苹果地图，不在 App 内自绘底图，因此不涉及审图号问题。
